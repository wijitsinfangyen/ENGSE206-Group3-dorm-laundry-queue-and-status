# ผลตรวจ ZIP ของปฐมพรเทียบ G1/G2 และ G3/G5 ล่าสุด

ตรวจเอกสาร `g4-architecture-pathomporn.md` และภาพ `context-after.png`, `container-after.png` ใน ZIP ที่ได้รับ ไม่ได้แก้ต้นฉบับของเพื่อน และยังไม่ได้ตรวจไฟล์ Draw.io เพราะไม่มีใน ZIP

## สิ่งที่ตรงกันแล้ว

- มี actor หลัก 3 กลุ่ม โดยทะเบียนชื่อเชื่อม Resident / Dorm Admin / Maid กับชื่อไทยตาม SRS
- มี Web App, API Application, Database, Scheduled Job ตรงกับ G3; Scheduled Job เรียก API และไม่เข้าฐานข้อมูลตรง
- External Notification Channel แยกเป็น Extension/TBD และส่งจริง Later; ไม่เดาผู้ให้บริการ
- API เป็นจุดตรวจสิทธิ์และกฎคิว; คง 5 นาทีสำหรับเตือนก่อนซักเสร็จ และ 10 นาทีสำหรับ no-show ตามฐาน
- G4 มีตาราง container, NFR mapping, Decision card 2 ใบ และ Spine walk

## สิ่งที่ต้องแก้/เพิ่มก่อนรวมส่ง

1. **ส่ง source ภาพ:** ZIP มี PNG สองภาพกับ Markdown เท่านั้น ยังไม่มี `context-after.drawio` และ `container-after.drawio` ซึ่งโจทย์บังคับ ขอไฟล์ต้นฉบับจากปฐมพร ไม่ควรติ๊กว่าได้รับครบแล้ว เอกสารมีลิงก์ไป source และสคริปต์ แต่สิ่งเหล่านั้นไม่อยู่ใน ZIP นี้
2. **อัปเดตฐาน G2:** เปลี่ยนข้อความว่าไม่ได้รับ G2/ยังไม่มี requirement ใหม่ ให้ตรงกับ G2 ฉบับแก้ไขที่เพิ่ม FR-FX-03, FR-FX-04, DR-FX-02 และ BR-FX-02 แล้ว ทั้งหมดยัง Proposed ไม่ใช่ baseline Approved
3. **เชื่อมแจ้งเตือนในเว็บ:** G4 §4.3, §4.6 SP-FX-03/04/06 และ DD-FX-01/05 ให้อ้าง FR-FX-03, US-FX-02, UC-FX-02, AC-FX-06 ระบุว่าสร้างรายการได้เมื่อไม่ได้เปิดเว็บ และเจ้าของอ่านย้อนหลังได้แม้ไม่ opt-in ภายนอก ไม่ใช่ browser push
4. **เชื่อม audit:** ใช้ FR-FX-04/DR-FX-02/BR-FX-02, US-FX-03, UC-FX-03 และ AC-FX-07–09 แทนข้อเสนอ DR-FX-AUD-01 ของ G4 เพื่อไม่สร้างรหัสข้อมูลซ้ำซ้อนกับ G2
5. **ระบุผลเมื่อบันทึก audit ล้มเหลว:** ใน C2/C3, SP-FX-02 และ Decision card ที่เกี่ยวข้อง ให้ชัดว่าสถานะกับ audit บันทึกใน transaction เดียวกันตามข้อเสนอ G3/G5; หาก audit ล้มเหลว rollback สถานะเดิม ไม่ยืนยันหรือแจ้งว่าสถานะใหม่สำเร็จ ตาม AC-FX-08 ข้อความในภาพที่ว่า transaction/proposed audit ยังไม่อธิบายเงื่อนไขนี้ครบ สามารถเสริมด้วยหมายเหตุในภาพหรือคำอธิบายประกอบ
6. **เพิ่มเส้นทางอ่าน audit:** ผู้ดูแลที่มีสิทธิ์ → Web App → API ตรวจ BR-FX-02 → Database → ผลอ่านแบบง่าย คง Build now ตาม UC-FX-03/AC-FX-09; ปฏิเสธนักศึกษาอ่านและการแก้/ลบผ่านงานทั่วไป รายงาน/ค้นหาขั้นสูงจึงค่อย Later ภาพปัจจุบันยังไม่ระบุการอ่าน audit ในหน้าที่ของ Web App/ผู้ดูแลอย่างชัดเจน
7. **แก้ checklist ให้ตรงสิ่งที่ได้รับจริง:** ไม่ถือว่าผู้ตรวจได้รับ/เปิด Draw.io แล้ว และไม่ติ๊กแทนการอ่านของปฐมพร/การตรวจโดยมนุษย์ ให้อัปเดตข้อความรอ ID เว็บ/audit เป็นรอเทียบ ID และภาพร่วมกันแทน

## ข้อความส่งต่อปฐมพร

ตรวจ G4 แล้ว ชื่อ actor/container และแนวทางภาพตรงกับ G3/G5 ครับ ขอไฟล์ context-after.drawio กับ container-after.drawio เพิ่ม และอัปเดตตาม G2 ฉบับแก้ไข: FR-FX-03 สำหรับเว็บแจ้งเตือน กับ FR-FX-04/DR-FX-02/BR-FX-02 สำหรับ audit ใช้รหัสเหล่านี้แทน DR-FX-AUD-01 เพิ่มให้ชัดว่าบันทึกสถานะพร้อม audit ถ้าล้มเหลวไม่เปลี่ยนสถานะ/ไม่แจ้งสำเร็จ และมีทางให้ผู้ดูแลที่มีสิทธิ์อ่านประวัติแบบง่าย รายงานขั้นสูงเลื่อนได้ครับ

## สถานะ

ตรวจระดับเอกสารและภาพที่แนบแล้ว ยังไม่ใช่การทดสอบระบบจริง ไม่ได้กรอกคำตอบการใช้ AI หรือคำรับรองของสมาชิก ชุดนี้ยังไม่ครบพร้อมส่งจนกว่าจะได้ source ภาพและปรับ G4 ให้ตรง G2 ล่าสุด
