## ส่วนที่ 1 — Core Twist: Accessibility + Offline (บังคับ)

### 1.1 Frame และ Scope ที่เปลี่ยนไปจาก Twist
- **In scope (เพิ่ม):** 
  - ระบบรองรับการใช้งานสำหรับผู้พิการทางสายตา (Screen Reader, Audio Prompt, ระบบสั่นแจ้งเตือน)[cite: 1, 5]
  - โหมดการทำงานแบบออฟไลน์ (Offline Mode) สำหรับตู้ควบคุมเครื่องซักผ้าเมื่ออินเทอร์เน็ตล่ม และระบบซิงค์ข้อมูลอัตโนมัติเมื่อกลับมาออนไลน์[cite: 1, 5]
- **Out of scope (ยังไม่ทำ):** 
  - การปรับปรุงหน้าจอแสดงผลกายภาพทั้งหมดให้เป็นจอสัมผัสขนาดใหญ่พิเศษสำหรับผู้พิการทางสายตา (เกินงบและเวลา)

### 1.2 Stakeholder ที่เพิ่ม/เปลี่ยน
| รหัส | บทบาท | ความต้องการ/ข้อกังวลจาก twist นี้ |
|---|---|---|
| ST-01 | นักศึกษาผู้พิการทางสายตา (ผู้ใช้กลุ่มใหม่) | ต้องการความสะดวกในการเข้าถึงสถานะเครื่องซักผ้าและกดจองโดยไม่ต้องอาศัยการมองเห็นหน้าจอ[cite: 1, 5] |
| ST-02 | ผู้ดูแลหอพัก / เจ้าหน้าที่ซ่อมบำรุง | กังวลเรื่องข้อมูลคิวหรือรายได้สูญหายเมื่อระบบอินเทอร์เน็ตของหอพักขัดข้องชั่วคราว[cite: 1, 5] |

| E-2 | "อินเทอร์เน็ตหอพักชอบหลุดบ่อย บางทีเน็ตตัดกลางคันข้อมูลจองคิวหายหมด ลูกบ้านมาโวยวาย"[cite: 1, 5] | Need / Fact |

### 1.4 Requirement Backlog (Core)

| REQ-ID | Requirement Statement | Type (FR/NFR/Constraint/Issue) | Priority (MoSCoW) | Trace (E-ID) | เหตุผล priority |
|---|---|---|---|---|---|
| R-1 | ระบบต้องรองรับการทำงานร่วมกับโปรแกรมอ่านหน้าจอ (Screen Reader) และมีคำอธิบายเสียงสำหรับทุกปุ่มกด | NFR (Accessibility) | Must Have | E-1 | เป็นข้อบังคับของ Twist เพื่อให้ผู้พิการทางสายตาใช้งานได้พื้นฐาน[cite: 1, 5] |
| R-2 | แอปพลิเคชันต้องสามารถแจ้งเตือนสถานะคิวและการซักเสร็จสิ้นผ่านระบบสั่นและเสียงอ่านได้ | FR | Should Have | E-1 | ช่วยเพิ่มความสะดวกให้ผู้พิการทางสายตาไม่ต้องคอยเปิดหน้าจอเช็ค[cite: 1, 5] |

### 1.5 Issue / สิ่งที่ยังไม่ยืนยัน
- **ISSUE-1:** ข้อมูลความจุหน่วยความจำออฟไลน์ที่ AI อ้างว่าเก็บได้ "เป็นล้านรายการ" เป็นข้อมูลที่เกินจริงและถูกแต่งขึ้นโดย AI จึงถูกบันทึกแยกเป็นประเด็นความเสี่ยงและจำกัดขอบเขตการจัดเก็บตามฮาร์ดแวร์จริง[cite: 1, 5]

## ส่วนที่ 2 — Mini Twist (เลือก 1: A หรือ B)

### 2.1 สถานการณ์ที่เลือกและผลกระทบ
- **เลือก:** B. Cut Scope (งบถูกตัดลงครึ่งหนึ่ง)[cite: 1, 5]
- **ผลกระทบ:** ไม่สามารถพัฒนาระบบ Hardware ใหม่ที่หน้าตู้เครื่องซักผ้าได้ครบทุกฟีเจอร์ ต้องตัดฟีเจอร์ที่ใช้ต้นทุนสูงออก และเน้นใช้ Software/App ที่มีอยู่เดิมในการแก้ปัญหา[cite: 1, 5]

### 2.2 Requirement / Decision ใหม่ (อย่างน้อย 2)
| ID | Requirement / Decision | เหตุผล | Trace |
|---|---|---|---|
| M-1 | ตัดการพัฒนาระบบสแกนคิวอาร์โค้ดหน้าตู้สำหรับการยืนยันตัวตนโหมดออฟไลน์ (Cut Scope) เปลี่ยนไปใช้ระบบกดรหัส PIN 4 หลักที่แป้นพิมพ์เดิมแทน | เพื่อลดต้นทุนค่า Hardware ลง 50% ตามงบที่ถูกตัด แต่ยังคงความสามารถในการยืนยันตัวตนออฟไลน์ไว้ได้[cite: 1, 5] | Core R-3 |
| M-2 | เลื่อนการทำระบบแจ้งเตือนผ่าน SMS ออกไป (Cut Scope) และใช้การแจ้งเตือนผ่านระบบสั่น/อ่านออกเสียงของตัวเครื่องสมาร์ทโฟนแทน | ลดค่าใช้จ่ายรายเดือนจากการส่ง SMS แต่ยังตอบโจทย์ Requirement ด้าน Accessibility[cite: 1, 5] | Core R-2 |
